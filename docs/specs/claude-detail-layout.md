# Claude／Codex 頁「方案 C」與 Claude 明細資料

狀態：已定案，實作中（2026-11-12）。版面模擬圖：https://claude.ai/artifact/8rzn2QiCWDzNeXLyWPPFTH （私人頁面）

## Problem Statement

RLCD 裝置的 Claude 頁只顯示 5 小時與 7 天兩個剩餘百分比，而且只在使用者於 Claude Code 中有動作時才更新。使用者實際擁有、也想在桌上一眼看到的額度資訊，例如 Fable 週額度、可兌換的重設額度與其到期日、加購用量花費，都不在裝置上。Codex 頁的版面和 Claude 頁不同，兩頁之間比較困難。長按 BOOT 在這兩頁上會默默切換天氣時鐘的秒數設定，使用者看不到效果。

## Solution

Claude 頁與 Codex 頁都改成「橫條清單」版面（方案 C）：每種額度一列，左邊名稱、中間進度條、右邊數字、條下方是重設時間。最下方區塊預設顯示重設額度，長按 BOOT 切換成使用統計（今日 token、7 天 token、正在執行數）。

Claude 頁新增 Fable 週額度、重設額度（分種類、含到期日）與加購用量花費。這些資料由 Claude Code plugin 每 15 分鐘向 Anthropic 用量端點查詢一次，companion 整理後經新的 BLE 特徵 `…de04` 送到裝置。舊韌體、舊 companion 都不受影響。拿不到憑證時，裝置明確顯示「未登入」，而不是默默顯示 `--`。

## User Stories

1. 身為 Claude 訂閱使用者，我想在裝置上看到 Fable 週額度剩餘百分比，以便決定要不要使用 Fable。
2. 身為 Claude 訂閱使用者，我想看到 Fable 週額度何時重置，以便安排大型工作。
3. 身為 Claude 訂閱使用者，我想看到我有幾次可兌換的重設額度，以便在額度用完時知道還有補救方法。
4. 身為 Claude 訂閱使用者，我想分辨重設額度是「完整重設」、「Fable 重設」還是「部分重設」，以便知道兌換後會清掉哪些額度。
5. 身為 Claude 訂閱使用者，我想看到每筆重設額度的到期日，以便在過期前使用。
6. 身為 Claude 訂閱使用者，當重設額度超過兩筆時，我想知道還有更多，以便到 Claude 設定頁查看完整清單。
7. 身為開啟加購用量的使用者，我想看到本月已花費金額與上限，以便控制花費。
8. 身為開啟加購用量的使用者，我想用進度條看到已花費比例，以便一眼判斷離上限多遠。
9. 身為沒有開啟加購用量的使用者，我想看到「未啟用」，以便知道這不是資料錯誤。
10. 身為使用非美元幣別的使用者，我想看到幣別代碼和金額，以便不會被誤導成美元。
11. 身為方案沒有 Fable 額度的使用者，我想看到「此方案無」，以便知道這一列不是故障。
12. 身為沒有重設額度的使用者，我想看到「無重設額度」，以便確認目前沒有可兌換的額度。
13. 身為長時間沒操作 Claude 的使用者，我想讓 5 小時與 7 天百分比仍然保持在 15 分鐘內的新鮮度，以便裝置上的數字可信。
14. 身為使用者，當明細超過 60 分鐘沒有更新時，我想看到 `--`，以便不會依據過期的數字做決定。
15. 身為使用 API key 或第三方 provider 登入的使用者，我想看到「未登入」，以便知道為什麼明細沒有資料。
16. 身為使用者，當 token 失效（端點回 401／403）時，我想看到「未登入」，以便知道要重新登入 Claude。
17. 身為使用者，當端點限流（429）時，我想繼續看到上次的數字，直到它過期，以便畫面不會因暫時的限流而變空。
18. 身為同時開好幾個 Claude 對話的使用者，我不希望每個對話都各自查一次用量，以便不消耗我自己 `/usage` 共用的限流額度。
19. 身為使用者，我想在 Claude 頁長按 BOOT 切換到使用統計，以便看到今日與 7 天 token 數和正在執行數。
20. 身為使用者，我想在 Codex 頁長按 BOOT 做一樣的切換，以便兩頁操作一致。
21. 身為使用者，我想讓兩頁各自記住目前顯示的是哪一個區塊，以便在 Claude 頁切換時不會改到 Codex 頁。
22. 身為使用者，我想看到下方區塊左下角有兩個小方塊，標示目前在哪一個區塊，以便知道這裡可以切換。
23. 身為使用者，重開機後我想回到預設的重設額度區塊，以便行為可預期。
24. 身為使用者，我不希望在這兩頁長按 BOOT 時改到天氣時鐘的秒數設定，以便設定不會在不知情時被改掉。
25. 身為 Codex 使用者，我想讓 Codex 頁也用同樣的橫條清單，以便和 Claude 頁直接比較。
26. 身為 Codex 使用者，我想在 Codex 頁看到重設額度總數和最近一筆的到期日，以便知道最急的那一筆。
27. 身為 Codex 使用者，我想讓付費額度列只顯示餘額數字、不畫進度條，因為 Codex 沒有回報上限。
28. 身為還在用舊韌體的使用者，更新 companion 後我的 Claude 頁與 Codex 頁要和以前一樣正常。

32. 身為維護者，我想用一個 debug 指令把 companion 送出的 `…de04` 內容解碼成文字，以便除錯。
33. 身為維護者，我想讓 companion 與韌體用同一組二進位測試向量測試，以便兩端對格式的理解一致。
34. 身為維護者，我想在不安裝 Claude CLI 的情況下測試 plugin 的查詢判斷，以便在任何機器上都能跑測試。
35. 身為維護者，我想在模擬器裡看到 Claude 頁與 Codex 頁的新預覽，以便附在 PR 截圖並確認 Pages 的 WASM 建置不會壞。

## Implementation Decisions

### 資料來源：plugin

- plugin 每個 session 啟動時檢查一次，之後每 5 分鐘檢查一次是否該查詢。檢查只讀本機檔案；真正向端點查詢最多每 15 分鐘一次（見下面的規則）。
- 查詢使用 Claude Code 自己的憑證：先取得不透明的憑證 handle，再透過引擎的 HTTP 介面送出，token 不經過 plugin。端點是 `https://api.anthropic.com/api/oauth/usage?cedar_ember=1`，帶 `anthropic-beta: oauth-2025-04-20` 標頭。
- 「要不要查」由一個純函式決定，輸入是上次成功時間、`fetching_at`、`retry_until`、現在時間，輸出是「查」或「不查」：
  - 上次成功距今不到 15 分鐘 → 不查；
  - `fetching_at` 距今不到 60 秒（另一個 session 正在查）→ 不查；
  - 現在早於 `retry_until`（上次收到 429）→ 不查；
  - 否則查，並先寫入 `fetching_at`。
- plugin 只存原始回應，不解析。明細檔是獨立的 `claude-usage-detail.json`，和既有的 `claude-rate-limits.json` 放在同一個目錄。不能寫進既有檔案，因為 statusLine 和 plugin 的既有邏輯每次都會覆蓋它。
- 明細檔結構：

  ```json
  {
    "last_ok": { "captured_at": 1794378572, "body": { "...": "端點原始回應" } },
    "last_attempt": { "at": 1794378572, "result": "ok" },
    "fetching_at": 0,
    "retry_until": 0
  }
  ```

  `result` 是 `ok`、`no_credential`、`auth_rejected`（401／403）、`rate_limited`（429）、`error`（其他）其中之一。失敗時只更新 `last_attempt`，不覆蓋 `last_ok`。
- 拿不到第一方憑證（API key、第三方 provider、gateway）或引擎拒絕送出時，記為 `no_credential`。

### companion

- 新增一個明細模組，輸入是明細檔與既有速率檔的內容加上現在時間，輸出是 104 bytes 的 `…de04` frame。
- Fable：只認 `limits[]` 中 `kind` 為 `weekly_scoped`、`scope.model.display_name` 為 `Fable` 的項目。能解析 `limits[]` 就設定「Fable 已知」；找到 Fable 才設定「Fable 存在」。
- 重設額度：
  - 分類：`clears` 同時包含 `five_hour` 與 `seven_day` → 完整（1）；`label` 含 `Fable`（不分大小寫）→ Fable（2）；其他已知窗口 → 部分（3）；無法判斷 → 其他（0）。
  - 篩選：`paused` 為真、或 `starts_at` 晚於現在、或 `ends_at` 早於現在的項目不列出；`resets_left` 為 0 的也不列出。
  - 排序：`usable_now` 為真的優先，再按 `ends_at` 由近到遠。最多 2 筆，超過時設定「還有更多」。
- 加購用量：優先讀 `spend`（`used.amount_minor`、`limit.amount_minor`、`exponent`、`currency`、`enabled`），沒有時讀 `extra_usage`（`used_credits`、`monthly_limit`、`decimal_places`、`currency`、`is_enabled`）。幣別必須是 3 個大寫英文字母、小數位數必須在 0～9，否則金額標示為無效。
- `source_state`：`last_attempt.at` 不早於 `last_ok.captured_at` 時採用 `last_attempt.result`，否則為 `ok`；沒有明細檔時為 0（未知）。
- Claude 的 5h／7d：companion 比較明細檔 `last_ok` 與速率檔的 `captured_at`，取比較新的那一份 `five_hour`／`seven_day`（明細檔中 `utilization` 為已用百分比）。結果仍走既有的 `…de03` JSON，格式不變。
- BLE：
  - 只有在裝置的服務中找到 `…de04` 時才寫入。
  - 明細的產生失敗與寫入失敗都在 companion 內部接住並記 log，不得中斷 `…de02`、`…de03` 的傳送，也不得觸發重連。
  - 每次心跳重送同一份明細，只更新 `sent_at`，不讀取端點。
- debug 指令：把 frame 解碼成可讀文字。

### BLE 協定：`…de04` v1

UUID `7d8b6c20-8f6d-4b44-a0f8-1b6570c0de04`，write-with-response，和既有特徵一樣要求加密、認證、已配對。新特徵加在 `…de03` 之後，既有特徵的順序與行為不變。

固定 104 bytes，所有多位元組整數為 unsigned little-endian：

| Offset | 長度 | 欄位 | 說明 |
|---|---|---|---|
| 0 | 1 | `version` | 固定為 1 |
| 1 | 1 | `source_state` | 0 未知、1 正常、2 拿不到憑證、3 認證被拒、4 限流、5 其他錯誤 |
| 2 | 1 | `flags` | bit0 Fable 已知、bit1 Fable 存在、bit2 加購已知、bit3 加購啟用、bit4 金額有效、bit5 重設額度已知、bit6 還有更多重設額度、bit7 保留（必須為 0） |
| 3 | 1 | `grant_count` | 0～2 |
| 4 | 8 | `captured_at` | 最後一次成功查詢的 Unix 秒，0 表示從未成功 |
| 12 | 8 | `sent_at` | companion 送出時的 Unix 秒 |
| 20 | 2 | `fable_used_bp` | 已用比例，單位 0.01%，0～10000 |
| 22 | 8 | `fable_resets_at` | Unix 秒，0 表示未知 |
| 30 | 3 | `currency` | 大寫 ASCII，未知時全為 0 |
| 33 | 1 | `exponent` | 0～9，255 表示未知 |
| 34 | 8 | `spend_used` | 最小單位 |
| 42 | 8 | `spend_limit` | 最小單位，0 表示沒有上限 |
| 50 | 27 | `grant[0]` | 見下表 |
| 77 | 27 | `grant[1]` | 見下表 |

每筆重設額度（27 bytes）：

| Offset | 長度 | 欄位 | 說明 |
|---|---|---|---|
| 0 | 1 | `type` | 0 其他、1 完整、2 Fable、3 部分 |
| 1 | 1 | `clears` | bit0 five_hour、bit1 seven_day、bit2 seven_day_overage_included、bit3 其他窗口 |
| 2 | 1 | `state` | bit0 paused、bit1 usable_now |
| 3 | 8 | `resets_left` | |
| 11 | 8 | `resets_total` | |
| 19 | 8 | `ends_at` | Unix 秒，0 表示未知 |

未使用的重設額度槽全部填 0。韌體接受 104～180 bytes 的 frame，忽略 104 bytes 之後的內容；`version` 不是 1、保留位元不為 0、或欄位超出範圍時拒絕整個 frame。日後的破壞性變更改用新的特徵，不改 v1 的意義。

### 韌體

- 新的明細解析器與明細狀態獨立於既有 Claude 狀態。BLE 斷線時明細標記為無效。
- BLE 存取回呼要明確比對是哪一個特徵的 marker，再分派給 Codex、Claude 或 Claude 明細的處理函式。現行「有帶任何 `arg` 就當成 Claude」的寫法要改掉。
- 明細的顯示判斷是一個純函式，輸入明細狀態與現在的單調時間，輸出每一列要顯示的內容。規則依序是：
  1. 沒有收過明細，或 BLE 斷線 → 全部 `--`；
  2. `source_state` 為 2 或 3 → Fable 與付費寫「未登入」，下方區塊用大字寫「Claude 未登入」；
  3. `captured_at` 為 0，或資料年齡超過 60 分鐘 → 全部 `--`；
  4. 否則依各欄位與旗標顯示。資料年齡 = (`sent_at` − `captured_at`) + 收到 frame 後經過的單調時間；`sent_at` 早於 `captured_at` 時視為年齡未知，套用規則 3。
- 版面（Claude 頁，y 座標以內容區頂端為 0）：四列「5 小時、7 天、Fable、付費」，每列約 42px；分隔線之下是可切換的下方區塊。
  - 5 小時、7 天、Fable：進度條代表**剩餘**比例。
  - 付費：進度條代表**已花費**比例，右側數字是已花費百分比（例如 `20%`），條下方寫「已花費 $7.86 / $40.00」。金額不放在右側數字欄：Montserrat 24 下 `$1234.56` 寬 103px、`EUR 1234.56` 寬 146px，超過 82px 的數字欄。上限為 0 時不畫條、右側不顯示數字，條下方只寫「已花費 <金額>」。
- 版面（Codex 頁）：三列「5 小時、7 天、付費」；付費只顯示餘額或「無限」，不畫條；下方區塊顯示「完整重設 xN」與「最近 M/D 到期」，資料來自現有協定的重設額度總數與最近到期秒數。
- 下方區塊的兩種內容：
  - 重設額度：最多 2 列，每列「種類 xN」靠左、「M/D 到期」靠右；有更多時在區塊標題後加「+」。
  - 使用統計：今日、7 天、正在執行三欄。
- 長按 BOOT：在 Claude 頁或 Codex 頁時，切換該頁的下方區塊；兩頁各自一個記憶體中的狀態（atomic 值加版本計數器），不寫入設定，重開機回到重設額度區塊。其他頁的長按行為不變。
- 標籤用 ASCII `x`，不用 `×`，因為所有字型的字元範圍都不含 U+00D7。

### 字串

新增的使用者可見字串都放進 UI 文字目錄，四種語系（zh-TW、zh-CN、en、ja）都要有。zh-TW 至少包含：`5 小時`、`7 天`、`Fable`、`付費`、`重設於 %s`、`已花費 %s / %s`、`已花費 %s`、`餘額`、`重設額度`、`使用統計`、`完整重設`、`Fable 重設`、`部分重設`、`其他重設`、`%s 到期`、`最近 %s 到期`、`此方案無`、`未啟用`、`無重設額度`、`未登入`、`Claude 未登入`、`今日`、`7 天`、`正在執行`。日文字串必須通過目錄檢查工具的缺字檢查；有缺字時換用字型中已有的字詞，不重新產生字型。

## Testing Decisions

好的測試只檢查對外行為：給定輸入檔案或 frame，檢查輸出的 bytes 或顯示內容，不檢查內部函式怎麼拆。

測試接縫（由高到低，盡量少）：

1. **companion：「兩個檔案內容 + 現在時間 → 104 bytes frame」。** 用下面的共用向量比對完整輸出，另外涵蓋分類、篩選、排序、截斷旗標、幣別無效、`source_state` 推導、5h／7d 取新。前例：companion 的 `test_claude_usage.py`、`test_protocol.py`。
2. **companion BLE：既有的假 client 測試。** 涵蓋找不到 `…de04` 時跳過、明細產生失敗或寫入失敗不影響 `…de02`／`…de03`。前例：`test_ble.py`。
3. **韌體解析器：「bytes → 結構」。** 用同一組向量，加上長度不足、版本錯、保留位元、`grant_count` 超過 2、`exponent` 超範圍等拒絕案例。前例：`codex_usage_protocol_host_test.cpp`，以 g++ 編成獨立的 assert 程式。
4. **韌體顯示判斷：「明細狀態 + 現在時間 → 每列顯示內容」。** 涵蓋 `--`、未登入、過期、此方案無、未啟用、無重設額度、幣別代碼。前例：`codex_usage_state_model_host_test.cpp`。
5. **長按切換：** 兩頁狀態獨立、切換兩次回原狀。前例：`active_work_page_state_host_test.cpp`。
6. **plugin 查詢判斷：** 用 Node 內建測試執行器直接跑 TypeScript，涵蓋四條規則與邊界時間。另外以 dev-mod 實際載入一次，確認引擎接受模組間的 import。
7. **整體：** 模擬器原生建置與新預覽截圖；四種語系各建置一次韌體；實機相容矩陣，由使用者燒錄。

## Further Notes

- 端點與 `cedar_ember` 參數沒有公開文件，欄位名稱多為內部代號，隨時可能改變。所有解析都在 companion，欄位缺少時一律降級成「未知」，不讓整頁出錯。
- 新增 GATT 特徵後，已配對的 Windows 主機能否不重新配對就找到 `…de04`，只能在實機確認。companion 已要求不使用 GATT 快取，韌體也會送出 Service Changed，但這兩點都不是實測證明。
- 現行 Claude JSON payload 約 144～165 bytes，每 15 秒寫一次都正常，所以 104 bytes 的單次寫入不需要額外的 MTU 處理。
